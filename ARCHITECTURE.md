# MONO architecture

Single Gradle module (`:app`) with package boundaries that mirror the product areas.
Splitting into Gradle modules can come later; one module keeps cloud builds fast.

```
com.shoron.mono
├── MonoApplication, AppContainer   process entry + manual dependency container
├── core/design      LayoutMetrics (proportional sizing), MonoIconFilter
├── core/theme       MonoColors, MonoTheme (Material 3, dark only), Outfit + Sacramento fonts
├── launcher/        LauncherActivity (HOME), LauncherRoot (home ⇄ drawer), AppActionsMenu
│   ├── home/        HomeScreen, HomeViewModel
│   └── drawer/      DrawerScreen, DrawerViewModel, DrawerModel, AlphabetRail
├── widgets/         WidgetEngine (shared flows for home + lock), SystemShortcuts
│   ├── clock        TimeTicker, SecondTicker, ClockSnapshot, ClockFormatter, TimeInWords,
│   │                DialGeometry, RadialClock, WordClock
│   ├── date         DateLine, MonthTitle, WeekdayScript
│   ├── weather      OpenMeteo (urls, parsing, cache codec), WeatherRepository + WeatherWorker,
│   │                WeatherCodes, WeatherDetails
│   └── battery      BatteryState, BatteryMonitor, BatteryIndicator
├── lockscreen       LockScreenActivity, LockScreenContent, LockViewModel,
│                    LockScreenController (SCREEN_OFF), LockWallpaperSync
├── icons            (Phase 5 — Thin Line icon engine)
├── wallpaper        WallpaperSettings, WallpaperCatalog, WallpaperMath, WallpaperPreferences,
│                    WallpaperRepository (decode/import), WallpaperImage/Layer, WallpaperViewModel
├── apps             AppEntry, AppRepository, AppLauncher, AppSearch, IconCache, AppIcon,
│                    DefaultPins, DefaultAppResolver, PinnedApps
├── settings         SettingsActivity, SettingsNavHost/SettingsScreen, WallpaperScreen,
│                    SettingsViewModel, DefaultHome
└── data             LauncherPreferences, PinList, WidgetPreferences (DataStore "widgets"),
                     WidgetSettings / LockSettings
```

## Pattern

MVVM + repositories. Repositories expose `Flow`/`StateFlow`; ViewModels combine them with
`stateIn(WhileSubscribed(5s))`; screens collect with `collectAsStateWithLifecycle()`.
Dependencies are wired by hand in `AppContainer` (no DI framework, no reflection).

```
LauncherApps callbacks ──► AppRepository.apps ─┐
DataStore ──────────────► LauncherPreferences ─┼─► HomeViewModel ──► HomeScreen
TIME_TICK broadcast ────► TimeTicker ──────────┘   DrawerViewModel ─► DrawerScreen
```

## Key decisions

- **App identity** is `package/class|userSerial` (`AppKeys`), so work-profile apps are distinct
  and pins survive restarts. `AppEntry` holds no Android types → JVM-testable and Compose-stable.
- **App list** is event-driven (`LauncherApps.Callback`); never polled. No `QUERY_ALL_PACKAGES`.
- **Icons** load lazily off the main thread into an `LruCache` sized to 1/16 of the heap and are
  cleared only under real memory pressure (`onTrimMemory ≥ MODERATE`).
- **Clock** uses the system `TIME_TICK` broadcast (once a minute) and is subscribed only while
  the home screen is started. `ClockSnapshot` is compared by value, so only changed text recomposes.
- **Layout** is proportional: `LayoutMetrics` derives gutters, type and spacing from the space left
  after `WindowInsets.safeDrawing`. There are no hard-coded screen sizes; landscape switches to a
  two-column layout.
- **HOME activity**: `singleTask`, `excludeFromRecents`, `taskAffinity=""`, handles config changes
  itself; Back only closes the drawer; a Home press while visible returns to the home page.
- **Wallpaper** is drawn by MONO itself (not the system wallpaper), under the home content.
  Bitmaps are decoded straight to the display size with `ImageDecoder` (hardware allocation, so
  pixels live in GPU memory; EXIF orientation honoured) and kept in a 6-entry LRU. Changing focal
  point, dim or greyscale only changes draw parameters (`BiasAlignment`, colour matrix) — no
  re-decode. Imported photos are downscaled to ≤1800×3600 and re-encoded as WebP in
  app-private storage, so no storage permission or URI grant is needed. Built-ins are original
  procedural artwork generated by `tools/wallpapers/generate.py`. A future animated wallpaper
  would be another `WallpaperSettings.sourceId` handled inside `WallpaperLayer`.
- **Widgets** read from one `WidgetEngine`, shared by home and lock screen. Seconds come from a
  cold `SecondTicker` that runs only while a visible screen collects it and only when seconds
  are enabled; the clock passes the time as a `State` so per-second ticks are read in the
  dial's draw phase (or a tiny seconds `Text`), never recomposing the whole screen.
  Battery uses the sticky `ACTION_BATTERY_CHANGED` broadcast while visible.
- **Weather** (Open-Meteo, no key): `HttpURLConnection` + `org.json`, cached in DataStore,
  refreshed when the location/unit changes, hourly via WorkManager (network + battery-not-low
  constraints) and when a MONO screen becomes visible with a cache older than 30 minutes.
  Location is a city chosen by search — no location permission.
- **Lock screen** is an activity shown over the keyguard (see README). It never dismisses the
  keyguard itself; `requestDismissKeyguard` delegates to the system's secure UI.
- **Default home** uses `RoleManager.ROLE_HOME` on Android 10+, with a fallback to the system
  Home settings for OEM builds that suppress the dialog.

## Performance rules (apply to every phase)

1. No polling and no continuous animation by default.
2. Background work only through lifecycle-aware flows or WorkManager with constraints.
3. Lazy lists for anything that can grow; stable keys and content types.
4. Immutable UI state classes; pass the smallest state each composable needs.
5. Vector drawables for icons; compressed WebP for bitmaps.
6. New permissions must be justified in DEVELOPMENT_LOG.md.

## Permissions

Runtime permissions: **none**. Install-time (normal): `INTERNET` (weather), `SET_WALLPAPER`
(optional lock-wallpaper sync). Special, user-granted and optional: `SYSTEM_ALERT_WINDOW`
("Display over other apps", only so the MONO lock screen can appear after other apps). The manifest `<queries>` block lists only
launcher activities and the default-app intents used to choose the first home shortcuts.
